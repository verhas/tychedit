Why another Markdown editor?

mdship placeholders are HTML comments, so most editors and every browser show them as nothing at all. You edit blind and find out what mdship update thought of your edits only after you run it.

It shows them

Every placeholder is a small card in the preview, generated content is framed, and variable references carry a $name label. One switch gives you the reader's view.

It checks them

Unknown parameters, missing ones, wrong values, bad regular expressions and paths that point nowhere are underlined as you type.

It runs them

The mdship menu runs every command on the saved file, and one Undo takes back what mdship did.

Features

A native editor built on AppKit and SwiftUI. The Markdown renderer is written for the app: a library would hide the very comments this editor exists to show, and every block needs its source line for scroll sync.

Parameter suggestions

Type inside a placeholder and get its parameters, each with a one-line explanation. Values too: choices, file names from disk, scripts from .mdship/scripts/.

Follow links and references

⌘-click a from: path, a variable, a heading link or an INCLUDE range and land on the exact line.

Document structure

A window of only the headings. Drag a heading to move its whole section, or sideways to change its level.

Find and replace

Case, whole word and regular expressions with $1 groups. Replace All is a single undo.

Folding

Fold sections and placeholders, with a badge that says what is hidden. Saving, find and mdship still see everything.

Byte-faithful saving

mdship keeps checksums inside the file, so a save changes only what you edited: encoding, line endings, permissions and attributes stay.

Autosave that never interrupts

Saves after a pause, never mid-word, and never over a file that changed on disk. Changes made by git or a terminal are picked up when the window returns.

Scroll-synced preview

The preview follows the editor line by line, and clicking a link in it behaves like ⌘-clicking in the editor.

Configurable toolbar

Choose the buttons, their order and their icons (any SF Symbol) in Settings ▸ Toolbar.

Git, right in the margin

For a file in a git repository, Tychedit compares the text with the last commit and shows the difference on both sides of the window.

  • Green bars in the gutter, and green text in the preview, for added lines.
  • Blue bars and blue text for changed lines.
  • A red wedge where committed lines were deleted.
  • Hover a change to see the committed text; right-click to Revert This Line, Revert Whole Change or Restore Deleted Lines. Each is one undo.

Commit without leaving the editor. The Commit to Git toolbar button, or File ▸ Commit… (⌥⌘K), asks for a message and offers Commit, Commit + Push and Cancel. Only the edited file is committed, whatever else is staged, and an unsaved file is saved first.

Working with mdship

Tychedit starts one mdship mcp server on first use and keeps it running for every window, so commands do not pay Python's start-up time.

The mdship menu

  • Update Placeholders (⇧⌘U), or overwrite edits with --force
  • Update Table of Contents, Includes, Render Diagrams
  • Number and unnumber headings, fix levels, promote and demote
  • Format Tables, Semantic Line Breaks, Reflow Paragraphs
  • Validate Links, Check AI Placeholders, Add and Verify Checksum

Everything mdship prints goes to a console, live, and problems it reports with a line number join the editor's own in the problems menu.

Checks as you type

  • Unknown or missing parameters, with did you mean…? for typos
  • Values of the wrong kind, unknown strategy or format
  • Regular expressions that do not compile or capture the wrong number of groups
  • Combinations mdship rejects
  • Missing files, missing scripts, ranges past the end of a file
  • Unclosed tags, bad nesting, and generated content edited by hand

If mdship is not installed, mdship ▸ Install or Upgrade mdship… runs pip install --upgrade mdship in your login shell.

Install and build

Download the notarized .dmg from the latest release, drag Tychedit to Applications, and open a file. To build it yourself you need Xcode 26 and macOS 15 or later.

git clone https://github.com/verhas/tychedit.git
cd tychedit
./build.sh run            # build and launch
./build.sh run file.md    # ...on a file
./build.sh test           # unit tests
./build.sh dmg            # signed disk image (release)

Open a file from Finder's Open With, from Diptych, or with open -a Tychedit file.md. Tychedit registers as an alternate Markdown editor and becomes the default only if you say Yes when it asks at start-up.

Settings live in ~/.tychedit/settings.json as readable JSON; edits made by hand take effect when you switch back to the app.
